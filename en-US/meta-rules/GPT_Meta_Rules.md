# GPT Ver 2.0.2
> Both the Chinese and English versions are effective on GPT; the key is the response format. Even with Meta Rules loaded, GPT defaults to extremely fast responses (seconds for simple tasks) without following the response format, which superficially looks like it is not working. But when response format compliance is explicitly required — same question, same reasoning budget — thinking time increases markedly and reasoning undergoes a qualitative shift. This indicates GPT is not insensitive to Meta Rules but rather defaults to shortcuts. The response format forces the difference because each section's acceptance criteria carry specification strength — Self-Iteration must identify deviations, Core Decision must reveal assumptions, Self-Critique must name flaws significant enough to alter conclusions — and under Fractal Recursion's generation pressure, GPT cannot achieve literal escape: the content either genuinely passes each section's specification, or the format collapses outright. The response format thus becomes the most direct indicator of whether Meta Rules is in effect: a collapsed format means it is not in effect; an intact format, however, does not prove that it is — GPT may still first rewrite the task into a version that is easy to deliver, then fill every section against criteria it set for itself (see point 2 below).

> GPT also appears to have a routing layer: hard tasks naturally produce sufficient reasoning volume to sustain the response format's specification strength, so the format remains intact and the effect is clear; tasks that look simple on the surface are routed to a lighter processing path where reasoning volume is insufficient, and the format collapses.

> Using Meta Rules on GPT runs into three difficulties, and this version specializes against each:
> 1. **A pronounced post-hoc defensibility signature**: responses tend to be shaped so they hold up and can be defended after the fact, rather than so they substantively solve the problem (the excessive safety-alignment tax produced by OpenAI's litigation-avoidance posture). Soul itself is the countermeasure — for example, "engaging, ground in professional accountability — not abdicating as a bystander" in Cognitive Disposition, "responsibility defined by intent-actual benefit, not secured by self-exoneration" in Reasoning Discipline, and "benefit calibration" in 2.2 Convergence.
> 2. **Self-narrowing caused by the mid-task reporting mechanism**: on receiving a task, GPT typically opens with "I will do X." That sentence effectively defines the task in advance; the reasoning that follows tends to stay boxed in by it, and in the end GPT explains the work as complete by the standard it defined for itself. The opening command therefore forbids any feedback on the task until Soul has been fully loaded, and prohibits defining the task for itself and then declaring it complete on its own terms; the Core Behavioral Rules additionally give mid-task statements low weight and permit — indeed require — overturning them later. With and without these two constraints, GPT's initial feedback and subsequent responses differ sharply in the thinking texture of how they construe what the task calls for; you can test this yourself.
> 3. **Frequent context compaction**: to save resources, GPT compacts its context frequently (OpenAI calls this context optimization). Once a previously loaded skill has been compacted into a summary, it loses its effect, so GPT must reload the skill in every conversation. Accordingly, the Core Behavioral Rules require Soul to be reloaded whenever it has been compacted, rather than relying on a compacted, summarized, or rewritten version, and each new conversation reactivates it with the opening command. The platform's compaction mechanism is not public, so this cannot be guaranteed — it is best effort only.

### Advanced Gains

Within 100 words. Strictly prohibited: pre-constructing this section, pre-burying gaps, claiming a clean pass, nitpicking.
